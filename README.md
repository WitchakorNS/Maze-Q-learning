## เริ่มใช้ส่วนที่ 5

1. เปิด `play.cmd` ใหม่เพื่อใช้หน้าจอเวอร์ชันล่าสุด
2. เลือก **Q-learning**, **Curriculum** หรือ **Curric + Bonus** จากช่องข้างปุ่มโหลดโมเดล
3. กด **ให้ Q เดิน** เพื่อโหลดโมเดลของวิธีนั้นจากการเปรียบเทียบล่าสุดที่เสร็จสมบูรณ์

## ฝึกเปรียบเทียบสามวิธี

ดับเบิลคลิก `exploration.cmd` หรือรัน:

```powershell

```

ฝึก Q ปกติ, Q + Curriculum และ Q + Curriculum + Bonus จาก Q=0 ใช้ 100,000 action **ต่อวิธี ต่อ seed** รวม 1,500,000 action รวม warm-up และชนกำแพงทั้งหมด รันใหม่สร้าง `results/exploration-วันเวลา/` ไม่ทับผลเก่า การฝึกใช้ schedule และเงื่อนไข Curriculum เดียวกับส่วนที่ 4 ด้านล่าง

### โบนัสสอน AI อย่างไร

ใช้ `intrinsic_reward = beta / sqrt(N(next_state) + 1)` สำหรับการเดินเข้าช่องอื่นที่ยังไม่ใช่ G โดย N คือจำนวน visit ก่อน action นี้ ค่าเริ่มต้น beta=0.5: โบนัสสำหรับช่องใหม่ 0.5 ครั้งที่สองประมาณ 0.354 แล้วลดลงเรื่อย ๆ

- ใช้ `learning_reward = env_reward + intrinsic_reward` อัปเดต Q เท่านั้น กติกา Environment ไม่เปลี่ยน
- ชนกำแพงไม่ให้โบนัสและไม่นับ visit ส่วน G นับ visit แต่ไม่ให้โบนัส
- นับจุดเริ่มทุก reset เป็น visit โดยไม่มีโบนัส ตัวนับคงอยู่ข้าม episode และระดับ Curriculum เริ่มใหม่ต่อ training seed
- บันทึก `env_reward`, `intrinsic_reward`, `learning_reward` แยกใน training.csv การประเมินให้ intrinsic_reward=0 เสมอ และไม่เรียกตัวนับ
- snapshot เก็บค่า beta, กติกานับ, visit counts และโบนัสสะสมไว้ใน metadata ของโมเดล Bonus เพื่อดูหลักฐาน ไม่ใช่ระบบ resume การฝึกแบบ RNG ตรงทุกก้าว

นี่คือ **count-based exploration bonus** ที่ใช้ตำแหน่งจากประสบการณ์ ไม่ใช่ curiosity จาก neural network แบบคลิปต้นฉบับ และไม่ใช้ระยะทางถึงเป้าหมายคำนวณโบนัส

## หลักฐานส่วนที่ 4: Q ปกติกับ Curriculum

ดับเบิลคลิก `curriculum.cmd` หรือเปิด Terminal ในโฟลเดอร์นี้แล้วรัน:

```powershell
python curriculum.py --budget 100000 --seeds 0 1 2 3 4
```

หมายถึง 100,000 action ฝึก **ต่อวิธี ต่อ seed** รวม 2 วิธี × 5 seeds = 1,000,000 action รวมการเดินชนกำแพงและช่วงเริ่มใกล้เป้าหมายทั้งหมด งบเป็นจำนวนก้าวฝึก ไม่ใช่จำนวน episode และไม่นับการประเมินเป็นข้อมูลฝึก

Curriculum ใช้แผนที่เดิมและ Q-table เดิมภายในหนึ่ง seed โดยเลือกจุดเริ่ม 3 ระดับ:

| ระดับ | จุดเริ่มของ episode ฝึก |
|---|---|
| near | สุ่มจากช่องที่มีระยะทางเดินสั้นสุดถึง G เท่ากับ 1–4 ช่อง |
| middle | สุ่มจากช่องที่มีระยะ 5–10 ช่อง |
| real_start | ใช้ S จริง (1,1) ทุก episode |

เลื่อนระดับเมื่อ success rate ระหว่างฝึกอย่างน้อย 80% ใน 50 episode สมบูรณ์ล่าสุดของระดับนั้น หรือเมื่อ warm-up ระดับนั้นใช้ครบ 20,000 action โดยตรวจที่ขอบ episode (จึงอาจเกินได้ไม่เกินหนึ่ง episode) ตัวกันงบนี้ช่วยจำกัด warm-up แต่ถ้าตั้งงบรวมเล็กมากก็อาจหมดก่อนถึงขั้นสุดท้ายได้

**ผู้สอนใช้ BFS กับแผนที่เพื่อเลือกจุดเริ่มเท่านั้น** Agent ยังได้เพียงตำแหน่งปัจจุบันและ transition/reward ไม่ได้รับระยะหรือเส้นทางเฉลย ความรู้ของผู้สอนเป็นข้อได้เปรียบเพิ่มเติมที่ต้องเปิดเผย ไม่ใช่การทดลองที่ได้รับข้อมูลเท่ากันทุกด้าน

ทั้งสองวิธีใช้ alpha=0.1, gamma=0.95, epsilon เริ่ม 1.0 ลดด้วย 0.99995 ต่อ action จนต่ำสุด 0.05 โดยไม่รีเซ็ตเมื่อเลื่อนระดับ วิธีลด epsilon ต่อ action ทำให้เทียบกันได้แม้ความยาว episode ต่างกัน จึงฝึก Q ปกติใหม่ด้วย schedule นี้ด้วย ไม่ใช้ผลเดิมจากระยะที่ 3 มาเทียบความเร็วโดยตรง

| ตัวชี้วัด | Q ปกติ | Curriculum |

**Curriculum ในการตั้งค่านี้ไม่ได้เรียนรู้เร็วกว่า** ใช้ก้าวฝึกถึงจุดที่สังเกตพบ success ครั้งแรกเฉลี่ยมากกว่า 1,000 ก้าว ส่วนผลสุดท้ายเหมือนกัน ต้องรายงานข้อค้นพบนี้ตามจริง และไม่สรุปว่า Curriculum ดีขึ้นเสมอ

วัดผลจาก S จริงทุกครั้ง ไม่ใช้ความสำเร็จจากจุดเริ่มใกล้เป้าหมายแทนคะแนนประเมิน ประเมินทุก 1,000 action และที่จุด snapshot ที่กำหนดไว้ ค่าเวลาเรียนรู้จึงเป็นจุดที่สังเกตพบในกริด ไม่ใช่ก้าวแรกที่เรียนรู้ได้อย่างแน่นอน รายงานทั้งจำนวน seeds ที่เข้าเกณฑ์และค่าเฉลี่ยของกลุ่มนั้น

ตัวอย่างสมมติฐานสำหรับอภิปรายคือเวลาที่ใช้ warm-up อาจไม่คุ้มสำหรับโจทย์นี้ แต่ยังยืนยันสาเหตุจากการรันนี้อย่างเดียวไม่ได้ ไม่ปรับเงื่อนไขย้อนหลังให้ผลดูดีขึ้น ผลยังจำกัดบนแผนที่เดิมและจุดเริ่มประเมินเดิม

## ลอง Q-learning ที่ฝึกไว้แล้ว

1. เปิด `play.cmd`
2. กด **ให้ Q เดิน** โปรแกรมจะโหลดโมเดลจากรันล่าสุดที่เสร็จสมบูรณ์ หากยังไม่ได้เลือกโมเดลเอง
3. ปรับความเร็วและใช้ปุ่มพัก/เล่นต่อชุดเดียวกับ Random Agent ได้
4. กด **เริ่มรอบใหม่** หรือ R เพื่อกลับไปเล่นเอง
5. กด **โหลด Q-table** หากต้องการเลือก checkpoint อื่น เช่น ก่อนฝึกหรือหลังฝึก 100 episode แล้วกด **ให้ Q เดิน** อีกครั้ง

ข้อความข้างปุ่มบอก seed และ episode ของโมเดลที่โหลด ระหว่าง Q เดินจะแสดงค่า Q ของ action ที่เลือกในบรรทัดการเคลื่อนที่ Seed ในช่องกรอกของ Random ไม่มีผลต่อโมเดล Q ที่เลือก

**โหมดเดโม Q ใช้ epsilon=0 ไม่สุ่ม ไม่อัปเดต Q-table และไม่เปลี่ยน RNG ของ Agent** เมื่อ Q เท่ากันให้เลือกตัวแรกตามลำดับ UP, RIGHT, DOWN, LEFT คงที่ การเล่นซ้ำจากจุดเดิมจึงได้เส้นทางเดิม

โมเดลและรายงานที่ตรวจแล้ว:

- [รายงาน Q-learning เทียบกับ Random](results/qlearning-20261018-151912-832102/summary.md)
- [โมเดลก่อนฝึก seed 0](results/qlearning-20261018-151912-832102/models/seed-0-ep-0.json)
- [โมเดลหลังฝึก seed 0](results/qlearning-20261018-151912-832102/models/seed-0-ep-5000.json)

ผลจริง: ฝึก 5,000 episode ต่อ seed ทั้ง 5 seeds แล้วโหลดกลับมาประเมินหนึ่ง rollout ต่อโมเดล ทุกโมเดลถึงเป้าหมายใน **18 ก้าว รางวัล 83 ไม่ชนกำแพง** ส่วน Random ใช้กติกาเดิม สำเร็จ **214/1,000 รอบ (21.40%)** ผลนี้จำกัดที่แผนที่ จุดเริ่ม และเป้าหมายเดิม ไม่ได้พิสูจน์ว่าทำได้ทุกจุดเริ่มหรือแผนที่ใหม่

## ฝึก Q-learning ใหม่

ดับเบิลคลิก `train.cmd` หรือเปิด Terminal ในโฟลเดอร์นี้:

```powershell
python train.py
```

ค่าเริ่มต้น: 5,000 episode ต่อ seed, seeds 0–4, รอบละไม่เกิน 300 action, alpha=0.1, gamma=0.95, epsilon เริ่ม 1.0 ลดด้วยตัวคูณ 0.995 หลังแต่ละ episode และไม่ต่ำกว่า 0.05 ใช้ค่าเริ่มต้นที่กำหนดล่วงหน้า ไม่เลือกโมเดลจากคะแนนทดสอบ

ตัวอย่างรัน seed เดียวสำหรับตรวจการทำงาน:

```powershell
python train.py --episodes 5000 --seeds 0
```

รันหลาย seeds และตั้งพารามิเตอร์:

```powershell
python train.py --episodes 5000 --seeds 0 1 2 3 4 --alpha 0.1 --gamma 0.95 --epsilon-start 1 --epsilon-min 0.05 --epsilon-decay 0.995
```

การฝึกเริ่ม Q=0 ทุก state-action จากนั้นใช้ epsilon-greedy สำรวจและใช้สมการ:

```text
target = reward                         เมื่อถึงเป้าหมาย
target = reward + gamma * max Q(next)    กรณีอื่น รวมการหมดเวลาภายนอก
Q(state, action) += alpha * (target - Q(state, action))
```

Agent ได้เฉพาะตำแหน่ง และ transition จาก Environment ไม่ได้รับผนังทั้งแผนที่หรือเส้นทางเฉลย ตอนสำรวจและตอนเลือก Q สูงสุดยังเลือกทิศที่ชนกำแพงได้ ระหว่างฝึกสุ่มแก้ tie; ตอนประเมินแก้ tie แบบคงที่

เหตุผลที่ bootstrap เมื่อหมดก้าว: state มีเพียงตำแหน่ง ไม่รวมเวลาที่เหลือ จึงมองขีดจำกัด 300 ก้าวเป็น time limit ภายนอก ไม่ใช่ terminal state ของปัญหา การถึงเป้าหมายเท่านั้นที่ตัดค่ารางวัลอนาคต

การฝึกสร้างโฟลเดอร์ใหม่ `results/qlearning-วันเวลา/` ทุกครั้ง โดยเก็บ:

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `training.csv` | รางวัล/ก้าวทุก episode ระหว่างฝึก, epsilon และจำนวน training actions สะสม |
| `evaluation.csv` | ผล greedy ระหว่างฝึก ใช้ Environment แยกและไม่เปลี่ยนการฝึก |
| `models/seed-N-ep-K.json` | Q-table ก่อนฝึก, หลัง 10/100/500/1000 episode และตอนจบ ตามงบที่กำหนด |
| `final_evaluation.csv` | ผลประเมินหลังโหลดโมเดลสุดท้ายของแต่ละ seed |
| `random_evaluation.csv` | Random baseline ที่รันเทียบในรอบนี้ |
| `comparison.csv` | ตัวชี้วัดเทียบกัน รวมต้นทุน action สำหรับฝึก |
| `demo_path.csv` | เส้นทางของโมเดลจาก seed แรกที่ระบุ ไม่ได้เลือก seed ที่คะแนนดีที่สุด |
| `summary.json` / `summary.md` | พารามิเตอร์ ผลจริง ขอบเขตการสรุป และ source hash |

ประเมินระหว่างฝึกทุก 100 episode และตามจุด snapshot แต่ไม่หยุดก่อนครบงบเพราะคะแนนดี และไม่เลือก checkpoint ที่คะแนนดีที่สุด รางวัลจากการฝึกที่ยังสุ่มจึงแยกจากผลประเมิน greedy

โหลดแล้วประเมินโดยไม่ฝึกใหม่:

```powershell
python train.py --evaluate "results/qlearning-20261018-151912-832102/models/seed-0-ep-5000.json"
```

หากโมเดลฝึกด้วย `--max-steps` อื่น ต้องใส่ค่าเดียวกันตอน `--evaluate` โปรแกรมตรวจแผนที่ จุดเริ่ม เป้าหมาย รางวัล ขีดจำกัดก้าว ลำดับ action ขนาดตาราง และตัวเลขใน Q-table ก่อนใช้โมเดล ไฟล์ JSON ที่ไม่ถูกต้องจะถูกปฏิเสธ

โมเดลนี้บันทึกสำหรับโหลดเพื่อประเมิน/เดโม ยังไม่เก็บสถานะ RNG เพื่อ resume การฝึกให้เหมือนการฝึกต่อเนื่องทุกประการ

### วิธีสาธิตก่อน–หลังฝึก

1. เล่น Random หนึ่งรอบ เพื่อให้เห็นการเดินวนและชนกำแพง
2. โหลด `seed-0-ep-0.json` แล้วให้ Q เดิน: ตารางยังเป็นศูนย์ จึงเลือก UP ซ้ำตามกติกา tie ไม่ใช่การเดินสุ่ม
3. โหลด `seed-0-ep-10.json` เพื่อดูผลช่วงต้น
4. โหลด `seed-0-ep-100.json` และ `seed-0-ep-5000.json` เพื่อเทียบกับหลังเรียนรู้
5. แสดงรายงานและอธิบายว่าผลนี้ทดสอบจากจุดเริ่มเดิมบนแผนที่เดิม

การประเมิน Q ในระยะนี้ใช้หนึ่ง rollout ต่อ training seed เพราะนโยบายเป็น deterministic ไม่อ้างว่าเล่นซ้ำ 100 ครั้งแล้วเป็นตัวอย่างอิสระ 100 ตัว ส่วน Random มีความสุ่มในแต่ละ rollout จึงใช้หลายรอบในการประมาณ success rate

ระยะนี้ตั้งงบฝึกเป็นจำนวน episode ควรอ่านต้นทุน action จริงประกอบ และเมื่อเพิ่ม Curriculum/Bonus ต้องจัดงบ action ให้เท่ากันก่อนสรุปความเร็วในการเรียนรู้

## ดู Random Agent เล่นบนหน้าจอ

1. เปิดเกมด้วย `play.cmd` หรือ `python app.py`
2. ใส่ Seed เป็นจำนวนเต็ม เช่น `0` แล้วกด **สุ่มเดิน 1 รอบ**
3. เลือกความเร็ว ช้า / ปกติ / เร็ว และกด **พัก / เล่นต่อ** ได้
4. Agent จะหยุดเมื่อถึงเป้าหมายหรือครบ 300 ก้าว
5. กด **เริ่มรอบใหม่** หรือ R เพื่อยกเลิกการสุ่ม กลับไปเล่นเอง และล้างสถิติ

ระหว่างสุ่มหรือพัก ปุ่มเดินเองจะไม่แทรกแซง Agent เปลี่ยน Seed แล้วกดสุ่มเดินอีกครั้งเพื่อเริ่มรอบใหม่ ส่วนการเริ่มด้วย Seed เดิมจะได้การเดินเดิม

โหมดหน้าจอใช้ episode 1 ของ Seed ที่เลือก ตรงกับแถว episode 1 ในผลจาก `baseline.py` เมื่อใช้ max_steps=300 เหมือนกัน **เดโมบนหน้าจอไม่เขียนผลการทดลองลงไฟล์** ให้ใช้คำสั่งด้านล่างสำหรับเก็บหลักฐาน baseline

## กติกาที่ใช้

แผนที่คงที่ 10×10 จุดเริ่ม (1,1) เป้าหมาย (8,8) โดยแถวและคอลัมน์เริ่มนับจาก 0 ไม่มีการเดินทแยงหรือกับดักในระยะนี้

| ผลของหนึ่ง action | รางวัล | ผลต่อตำแหน่ง |
|---|---:|---|
| เดินเข้าช่องว่าง/จุดเริ่ม | -1 | ย้ายหนึ่งช่อง |
| ชนกำแพงหรือขอบแผนที่ | -5 | อยู่ที่เดิม |
| เดินถึงเป้าหมาย | +100 | จบรอบสำเร็จ |

หนึ่ง action ได้รางวัลเพียงรายการเดียว เช่น เดินถึงเป้าหมายได้ +100 ไม่หักค่าก้าวเพิ่ม การชนกำแพงนับเป็นหนึ่งก้าวด้วย

- จบรอบเมื่อถึงเป้าหมาย หรือพยายามเดินครบ 300 ครั้ง
- หากถึงเป้าหมายตรงก้าวที่ 300 ให้ถือว่าสำเร็จ
- หลังจบรอบไม่รับการเดินเพิ่มจนกว่าจะ reset
- แสดงจำนวนก้าว รางวัลสะสม จำนวนครั้งชนกำแพง และตำแหน่งปัจจุบัน

## API สำหรับ Agent ในช่วงถัดไป

```python
from environment import Action, MazeEnv

env = MazeEnv()
state, info = env.reset()
state, reward, terminated, truncated, info = env.step(Action.RIGHT)
print(env.render())
```

- State คือ tuple `(row, column)`
- Action: `0=UP`, `1=RIGHT`, `2=DOWN`, `3=LEFT`
- `terminated=True`: ถึงเป้าหมาย
- `truncated=True`: ครบจำนวนก้าวก่อนถึงเป้าหมาย
- `info`: event, steps, total_reward, wall_hits, unique_cells, is_success
- `step()` หลังจบรอบจะยก `RuntimeError` เพื่อจับข้อผิดพลาดใน training loop
- อินเทอร์เฟซคืนค่าแบบ Gym แต่ยังไม่ใช่คลาส `gymnasium.Env` และไม่ต้องติดตั้ง Gymnasium
