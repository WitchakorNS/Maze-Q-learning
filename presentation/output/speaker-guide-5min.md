## สไลด์ 1 (0:00–0:30)

**จังหวะ:** เปิดสไลด์ 1 ชี้ S และ G ในภาพ ยังไม่สลับไปโปรแกรม

สวัสดีครับ โปรเจกต์นี้คือการให้ AI เรียนรู้เดินออกจากเขาวงกตด้วย Reinforcement Learning ครับ เป้าหมายคือเดินจาก S ไป G ให้สำเร็จและใช้ก้าวน้อย โดย Agent เรียนรู้จากการลองเดินและรางวัลที่ได้รับ ผมใช้ Q-learning เป็นวิธีหลัก แล้วทดลองเพิ่ม Curriculum Learning และโบนัสสำรวจ เพื่อดูว่าสองแนวคิดนี้ช่วยให้เรียนรู้เร็วขึ้นหรือไม่ครับ

## สไลด์ 2 (0:30–1:15)

**จังหวะ:** สไลด์ 2 ชี้ตำแหน่ง การเลือกทิศ และรางวัล เชื่อมกับสิ่งที่เรียน

ผมสร้าง Environment เป็นเขาวงกตตารางสิบคูณสิบ State คือตำแหน่งแถวและคอลัมน์ ส่วน Action มีขึ้น ขวา ลง และซ้ายครับ เดินปกติได้รางวัลลบหนึ่ง ชนกำแพงลบห้า และถึงเป้าหมายได้บวกหนึ่งร้อย จำกัดรอบละสามร้อยก้าว ข้อมูลฝึกจึงเกิดจากประสบการณ์ที่ Agent เล่นเอง ไม่ต้องมีชุดคำตอบติดป้ายกำกับ Q-learning เก็บค่าของแต่ละทิศใน Q-table แล้วปรับค่าจากรางวัลและสถานะถัดไป ช่วงฝึกใช้ epsilon-greedy เพื่อสลับระหว่างสำรวจและเลือกทิศที่คิดว่าดี ซึ่งเชื่อมกับเรื่อง exploration และ exploitation ที่เรียนครับ

## สไลด์ 3 (1:15–2:05)

**จังหวะ:** สไลด์ 3 อธิบายสองวิธีด้วยภาษาง่าย ไม่ลงรายละเอียดทุกพารามิเตอร์

ผมต่อยอดสองส่วนครับ ส่วนแรกคือ Curriculum Learning จัดบทเรียนจากง่ายไปยาก เริ่มใกล้เป้าหมาย จากนั้นเริ่มไกลขึ้น และสุดท้ายกลับมาที่ S จริง ผู้สอนใช้ระยะทางจาก BFS เพื่อเลือกจุดเริ่ม แต่ไม่ได้ส่งระยะหรือเส้นทางให้ Agent ส่วนที่สองคือโบนัสสำรวจ ให้รางวัลเพิ่มเมื่อเดินเข้าช่องที่ยังไม่ค่อยเคยไป ยิ่งกลับไปบ่อย โบนัสยิ่งลดลง ตัวอย่างช่องใหม่ได้โบนัสศูนย์จุดห้า ทำให้ค่าการเดินจากลบหนึ่งเป็นลบศูนย์จุดห้า โดยไม่ให้โบนัสตอนชนกำแพงหรือถึงเป้าหมาย ผมแยกรางวัลเกมกับโบนัสไว้ใน log และใช้โบนัสเฉพาะระหว่างฝึกครับ

## สไลด์ 4 (2:05–2:40)

**จังหวะ:** สไลด์ 4 เน้นหน่วย action และการทดสอบจาก S จริง

เพื่อเทียบให้ชัด ผมฝึกใหม่สามวิธี คือ Q ปกติ Q กับ Curriculum และ Q กับ Curriculum พร้อมโบนัส ทุกวิธีได้งบหนึ่งแสน action ต่อ seed ใช้ห้า seeds และนับทั้งการชนกำแพงกับช่วงเริ่มใกล้เป้าหมายรวมในงบครับ ระหว่างทางประเมินจาก S จริงบนแผนที่เดียวกัน ด้วย epsilon เป็นศูนย์ ไม่อัปเดต Q และไม่มีโบนัส ตัวชี้วัดคือความสำเร็จ จำนวนก้าว รางวัลเกม และจำนวน action ฝึกที่เริ่มสังเกตพบความสำเร็จครับ

## สไลด์ 5 (2:40–3:50)

**จังหวะ:** สไลด์ 5 ชี้แท่ง 5,800 / 6,800 / 7,400 แล้วชี้ผลสุดท้ายด้านขวา

ผลสุดท้ายทั้งสามวิธีสำเร็จครบห้าโมเดลต่อวิธี เดินถึงเป้าหมายในสิบแปดก้าว ได้รางวัลเกมแปดสิบสาม และไม่ชนกำแพงครับ แต่ถ้ามองความเร็วระหว่างฝึก จะเห็นความต่าง Q ปกติพบ greedy success ครั้งแรกเฉลี่ยที่ห้าพันแปดร้อย action ส่วน Curriculum อยู่ที่หกพันแปดร้อย และ Curriculum พร้อมโบนัสอยู่ที่เจ็ดพันสี่ร้อย ดังนั้นในการตั้งค่าชุดนี้ การเพิ่ม Curriculum และโบนัสยังไม่ช่วยให้เรียนรู้เร็วขึ้นครับ ตัวเลขนี้เป็นจุดที่สังเกตจากการประเมินเป็นช่วง ๆ ไม่ใช่ action แรกที่เรียนรู้ได้อย่างแน่นอน และผมไม่ได้เลือก seed หรือ checkpoint ที่ดีที่สุดมารายงาน ส่วนสาเหตุที่วิธีต่อยอดช้ากว่า ยังยืนยันจากการทดลองนี้อย่างเดียวไม่ได้ อาจเกี่ยวกับต้นทุนช่วง warm-up หรือความเหมาะสมกับแผนที่ขนาดนี้ ซึ่งต้องออกแบบทดลองเพิ่มครับ

## สไลด์ 6 (3:50–5:00)

**จังหวะ:** 3:50–4:30 สลับไปเกมและเดโม จากนั้นกลับสไลด์ 6 เพื่อสรุป 30 วินาที

ช่วงเดโม: ตอนนี้ให้ Random Agent สุ่มเดินสั้น ๆ จะเห็นว่าไม่มีนโยบายที่เรียนรู้ไว้ครับ จากนั้นผม reset แล้วเลือกโมเดลหลังฝึก ให้เดินจาก S เดิมโดยไม่เรียนรู้เพิ่ม ผลคือถึงเป้าหมายในสิบแปดก้าว รางวัลแปดสิบสาม ไม่ชนกำแพงครับ

ช่วงสรุป: งานนี้แสดงว่า Q-learning เรียนรู้แก้เขาวงกตที่กำหนดได้ และทำให้ผมทดลองเรื่องการสำรวจกับการจัดบทเรียนโดยวัดผลจริง อย่างไรก็ตามผลยังจำกัดที่แผนที่เดียวและจุดเริ่มเดิม การเพิ่มเทคนิคยังไม่ให้ประโยชน์ด้านความเร็วในชุดนี้ ถ้าพัฒนาต่อ ผมจะทดลองหลายแผนที่และแยกชุดสำหรับปรับค่ากับชุดประเมินก่อนสรุปว่าวิธีไหนดีกว่าครับ ขอบคุณครับ

## เตรียมก่อนเริ่มจับเวลา

1. เปิด PowerPoint และเกมด้วย play.cmd ก่อนเริ่มพูด ปิดหน้าต่างส่วนตัวที่อาจปรากฏตอนสลับหน้าจอ
2. กรอกชื่อผู้จัดทำ/สมาชิกในหน้าแรกหรือบอกชื่อเมื่อเปิดเรื่อง สไลด์ไม่มีชื่อสมมติ
3. ตั้ง Random seed=0 และความเร็วปกติ จากนั้นลองเลือก Curric + Bonus กดให้ Q เดิน ตรวจว่าแสดง seed 0 และ 100,000 ก้าว แล้ว reset ไว้
4. การเปลี่ยนวิธีจะล้างโมเดลที่เลือก โปรแกรมจึงต้องโหลดอัตโนมัติอีกครั้งเมื่อกดให้ Q เดิน อย่าย้ายโฟลเดอร์ผลออกจากโปรเจกต์
5. ซ้อมสลับหน้าต่างด้วยวิธีที่ถนัดอย่างน้อยหนึ่งรอบ ไม่เปิด terminal หรือเริ่มฝึกในช่วง 5 นาที
6. ถ้าเดโมเปิดไม่ได้ภายใน 5 วินาที ให้ใช้ภาพโปรแกรมจริงในสไลด์ 6 เป็นภาพสำรอง ภาพนั้นเป็น Q ปกติ seed 0 ไม่อ้างว่าเป็นวิดีโอเดโมสดหรือเป็นโมเดล Bonus
7. ถ้าเหลือเวลาไม่พอ ตัดการโชว์ Random ก่อน รักษาช่วงผลทดลองและข้อจำกัดไว้

## คำถามที่ควรเตรียม

**ทำไมเลือก Q-learning?**

State เป็นตำแหน่งบนตารางขนาดเล็กและ action มีเพียง 4 แบบ จึงใช้ Q-table ได้ อธิบายและตรวจ update ได้ง่าย งานนี้ยังไม่จำเป็นต้องใช้ neural network

**ส่วนไหนคือความรู้ที่เรียน?**

Agent/Environment, State/Action/Reward, Q-value, policy, epsilon-greedy และ exploration/exploitation ส่วน Curriculum กับ count bonus เป็นแนวคิดต่อยอดที่นำมาทดลอง

**ถ้ามี BFS แล้ว ทำไมไม่ใช้ BFS หาเส้นทางเลย?**

ถ้าต้องการหาเส้นทางบนแผนที่ที่รู้ครบ BFS เหมาะและแก้โจทย์นี้ได้โดยไม่ต้องฝึก แต่เป้าหมายโปรเจกต์คือศึกษาการเรียนรู้จากรางวัล BFS ในงานนี้ทำหน้าที่ teacher สำหรับจัดระดับและใช้ตรวจระยะอ้างอิง ไม่ได้เป็น policy ที่สั่ง Agent เดิน

**ข้อมูลฝึกคืออะไร แบ่ง train/test อย่างไร?**

ข้อมูลคือ transition ที่ Agent สร้างเองระหว่างเล่น จึงไม่ได้แบ่งภาพหรือแถวข้อมูลแบบ supervised learning รอบประเมินแยก Environment และไม่มี update แต่ยังใช้แผนที่เดิมกับ S เดิม จึงวัดผลบนโจทย์เดิม ไม่ใช่หลักฐาน generalization ไปแผนที่ใหม่

**ทำไมไม่ใช้ Precision, Recall หรือ F1?**

งานนี้เป็นการเลือก action เพื่อไปถึงเป้าหมาย ไม่ใช่การจำแนก label จึงใช้ success rate จำนวนก้าว รางวัลเกม และความเร็วการเรียนรู้ที่เหมาะกับโจทย์มากกว่า

**ทำไมรายงานความเร็วเป็น action แทน episode?**

Curriculum มีรอบที่เริ่มใกล้ G และอาจจบสั้นกว่า ถ้าให้จำนวน episode เท่ากัน ต้นทุนการโต้ตอบไม่เท่ากัน จึงให้จำนวน action เท่ากัน รวม warm-up และชนกำแพง

**โบนัสทำให้คะแนนสูงขึ้นเองหรือเปล่า?**

ระหว่างฝึกใช้รางวัลเกมบวกโบนัส แต่แยก log และประเมินด้วยรางวัลเกมเท่านั้น ไม่มีโบนัสหรือการเพิ่ม visit ระหว่างประเมิน คะแนน 83 จึงเป็นกติกาเดียวกันทุกวิธี

**ทำไมรางวัลสุดท้ายเป็น 83?**

18 action ประกอบด้วยเดินธรรมดา 17 ครั้งและ action ถึง G 1 ครั้ง จึงเท่ากับ 17×(-1)+100 = 83 โดย action ถึง G ได้ +100 ไม่หัก -1 ซ้ำ

**ทำไม Curriculum และโบนัสไม่ดีขึ้น?**

ผลชุดนี้แสดงเพียงว่ายังไม่ช่วยด้านความเร็วภายใต้ค่าที่กำหนด สาเหตุยังเป็นสมมติฐาน อาจต้องทดลองขนาดแผนที่และเงื่อนไขเพิ่มเติม ไม่ควรอ้างว่าพิสูจน์แล้วว่าเทคนิคเหล่านี้ไม่ดีทุกกรณี

**100% หมายถึงทดสอบกี่ครั้ง?**

ผลเปรียบเทียบหลักคือ 5 training seeds ต่อวิธี ทดสอบสุดท้ายหนึ่ง greedy rollout ต่อโมเดล สำเร็จ 5/5 นโยบายและ Environment เป็น deterministic การเล่นซ้ำโมเดลเดิมจึงไม่ใช่ตัวอย่างอิสระเพิ่ม

**Random baseline ได้เท่าไร?**

ผลเดิมสำเร็จ 214/1,000 รอบ หรือ 21.4% บนแผนที่/กติกาเดียวกัน จาก 5 seeds โดย Random ไม่มีการฝึก นี่เป็น baseline ของการสุ่ม ไม่เอามารวมคำนวณเวลาเรียนรู้กับสามวิธีที่ฝึกภายใต้งบ action

**เหมือนคลิปต้นฉบับแค่ไหน?**

รับแนวคิดจัดความยากและแรงจูงใจสำรวจมาประยุกต์ งานนี้ใช้ Q-table บนตารางและโบนัสจากการนับช่อง ไม่ได้ใช้ SAC หรือ curiosity จากโมเดลทำนายสถานะของต้นฉบับ

**ทำซ้ำผลได้อย่างไร?**

ใช้ exploration.cmd หรือ python exploration.py --budget 100000 --seeds 0 1 2 3 4 --bonus-beta 0.5 ผลใหม่แยกโฟลเดอร์ มี config, source hashes, logs และโมเดลทุกวิธีใน summary.json
